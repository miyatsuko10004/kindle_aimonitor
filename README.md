# kindle_aimonitor

Codex・Claude Code・Antigravity の利用枠と、Mac で動いている AI エージェントの状況を、使っていない Kindle に電子ペーパーのダッシュボードとして表示します。

- Mac 上で利用状況を収集し、白黒・JavaScript なしの HTML として LAN に配信します（ポート `8766`）。
- Kindle の「体験版ブラウザ」でも表示できるよう、table レイアウトと meta refresh（300秒）だけで構成しています。
- 他のアプリは不要です。単体で動きます。

## 動作環境

macOS、Python 3.10 以上、Google Chrome（画像方式で使用）。追加パッケージは不要です。監視するサービス（Codex / Claude Code）にログイン済みである必要があります。Antigravity のライブ取得にはアプリが起動している必要があります。

## 使い方

```sh
git clone git@github.com:miyatsuko10004/kindle_aimonitor.git
cd kindle_aimonitor
./kindlemon start        # バックグラウンドで起動し、Kindle 用の URL を表示
./kindlemon url          # URL を再表示
./kindlemon status
./kindlemon stop
```

表示された `http://<MacのIP>:8766/t/<トークン>` を Kindle のブラウザ（メニュー →「体験版ブラウザ」）で開き、ブックマークします。

- 起動直後は「初回データを収集しています」と表示されます。次の自動更新で中身が出ます。
- 初回起動時に、macOS のファイアウォールが Python の受信接続を許可するか尋ねる場合があります。
- Claude Code の利用枠は macOS のキーチェーンにある既存の認証情報を読みます。初回はキーチェーンへのアクセス許可を求められる場合があります。
- Mac を再起動したら、もう一度 `./kindlemon start` を実行してください。

## 表示内容と取得元

| サービス | 利用枠 | エージェント情報 |
|---|---|---|
| Codex | 5時間・週間の使用率とリセットまでの時間 | セッション、モデル |
| Claude Code | 5時間・週間（取得できる場合） | 起動中セッション、最後の応答モデル |
| Antigravity | モデル別の使用率 | language server の起動、最近の会話 |

各サービスの非公開 API や内部データを読むため、サービス側の変更で取得できなくなる場合があります。認証情報の書き換えや自動ログインは行いません。

## Kindle 側のコツ

- **スリープについて**: 最近のファームウェア（5.18 系など）では、脱獄しないとスクリーンセーバーを止められません。止めない場合は、数分間操作がないとダッシュボードが隠れます。常時表示したい場合は下の「脱獄（参考）」を参照してください。
- 古いファームウェアでは、ホーム画面の検索バーに `~ds` と入力して Enter するとスクリーンセーバーを無効にできる場合があります（再起動で元に戻ります）。
- 常時表示する場合は USB 給電したままにします。
- 端末を横向きにすると 2 列、縦向きでは 1 列のレイアウトになります。
- 時刻ボタンをタップすると、その場で再読み込みします。

## 脱獄（参考）

スクリーンセーバーを止めて常時表示するには、Kindle の脱獄が必要です。以下は Kindle Paperwhite 第10世代（PW4）・ファームウェア 5.18.1・広告なしモデルで実施した手順のメモです。

> [!WARNING]
> 脱獄は非公式の改造で、保証の対象外になる可能性があります。端末が起動しなくなるリスクもあります。自己責任で行ってください。手順やツールは更新されるため、必ず [Kindle Modding Wiki](https://kindlemodding.org/jailbreaking/index.html) の最新情報を確認してください。

### 1. 使える脱獄方法を調べる

Kindle の「設定 → 端末オプション → 端末情報」で、シリアル番号・ファームウェアのバージョン・ロック画面広告の有無を確認します。それを [Find my Jailbreak](https://kindlemodding.org/jailbreak-wizard.html) に入力すると、使える方法が表示されます。

PW4・5.18.1・広告なしの場合、使えるのは **SpiderCat** と **Sanctuary** です（AdBreak は広告付きモデル専用）。以下は SpiderCat の手順です。

### 2. 自動アップデートを防ぐ（容量を埋める）

脱獄の途中は Wi‑Fi をオンにする必要があります。その間に自動アップデートが入ると、脱獄できないファームウェアに更新されることがあります。それを防ぐため、Kindle のストレージを埋めて空きを 50〜90MB にしておきます（[公式ガイド](https://kindlemodding.org/jailbreaking/prevent-auto-update/)）。

1. Kindle を機内モードにし、USB で Mac に接続します。
2. Kindle 直下に `update*.bin` などのアップデートファイルがあれば削除します。
3. 空きが約 70MB になるまでダミーファイルを作ります。macOS 標準の `mkfile` だけで作れます。

```sh
K=/Volumes/Kindle
mkdir -p "$K/fill_disk"
i=0
while :; do
  free=$(df -m "$K" | awk 'NR==2{print $4}')
  left=$((free - 70)); [ $left -le 0 ] && break
  mkfile $(( left > 100 ? 100 : left ))m "$K/fill_disk/fill_$i.bin" || break
  sync; i=$((i + 1))
done
df -h "$K"
```

Kindle への書き込みは遅く、数 GB を埋めるには 30 分以上かかることがあります。途中で USB が外れたら、つなぎ直して再実行してください。

### 3. SpiderCat を実行する（[公式ガイド](https://kindlemodding.org/jailbreaking/SpiderCat/)）

1. 公式ガイドから `spidercat.azw3` を入手し、Kindle の `documents` フォルダにコピーします。Kindle のブラウザから直接ダウンロードすることもできます。
2. Kindle を取り出して USB を抜き、機内モードを解除して Wi‑Fi に接続します。終わるまで Wi‑Fi はオンのままにします。
3. ライブラリから「SpiderCat」を開きます。しばらく画面が白いままになり、そのあと文字が流れ始めます。
4. 「アプリケーションエラー」が出ても無視します。
5. 「Restarting Kindle」と表示されて再起動したら成功です。最後の行が `abort:no-firm` なら非対応です。
6. Kindle ストアを開くなど、他の操作は終わるまでしないでください。

### 4. 脱獄後の後片付け

1. Kindle 直下に `.bin` のアップデートファイルがあれば削除します。
2. 容量埋めのダミーファイルを削除します（脱獄後はアップデートがブロックされます）。

```sh
rm -rf /Volumes/Kindle/fill_disk
```

3. 公式 Wiki の「[What's Next?](https://kindlemodding.org/jailbreaking/whats-next/index.html)」も確認しておきます。

### 5. ダッシュボードを常時表示する

脱獄済みの Kindle では、ライブラリに置いたシェルスクリプト（[スクリプトレット](https://kindlemodding.org/kindle-dev/scriptlets.html)）をタップで実行できます。このリポジトリの `kindle/` に、常時表示用のスクリプトレットを用意しています。

```sh
./kindlemon start      # サーバーを起動（トークンが生成される）
./kindlemon install    # USB 接続中の Kindle に、URL を埋め込んだスクリプトを転送
```

Kindle を取り出して USB を抜くと、ライブラリに次の 2 つが表示されます。

| 項目 | 動作 |
|---|---|
| AI Monitor - Start | スクリーンセーバーを止め、ダッシュボード画像を 5 分ごとに全画面へ描画する |
| AI Monitor - Stop | 描画を止め、スクリーンセーバーを元に戻す |

**画像方式の仕組み**: Kindle のブラウザは URL 欄を消せず、横向きにもならないため、Mac 側でダッシュボードを画像にして Kindle の画面へ直接描きます。

- Mac 側は 5 分ごとに、ヘッドレスの Google Chrome でダッシュボードを撮影し、`sips` で回転・グレースケール化して `/img/<トークン>.png` で配信します。**Google Chrome が必要です**（別の場所にある場合は環境変数 `KINDLE_CHROME` でパスを指定）。
- Kindle 側は 5 分ごとに画像を取得し、`eips` で全画面に描きます（10 回に 1 回は全面リフレッシュで残像を消去）。
- 向きは kindle ロゴが左に来る横向きです。ロゴを右にしたい場合は `kindle_server.py --rotate 90` で起動します。
- Kindle の時計やバッテリー表示（縦向きの上端）は画像の上に重なって描かれるため、その部分は画像側を空白にしています。

**使い方の注意**

- **終了は電源ボタン**です。押すとスリープに入り、描画も止まります。もう一度押すといつもの画面に戻ります。
- 表示中に画面をタッチすると、見えない下のライブラリが反応して本が開くことがあります。表示中は触らないでください。
- Mac の IP アドレスやトークンが変わったら、もう一度 `./kindlemon install` を実行してください。
- Kindle を再起動するとスクリーンセーバーは元に戻ります。再起動後は「AI Monitor - Start」をもう一度タップします。
- 常時表示中は USB 給電しておくことをおすすめします。
- ブラウザで見る場合は、`./kindlemon url` の URL を Kindle のブラウザで開きます（URL 欄は表示されます）。

## エージェント受信箱ボード（2台目向け）

どこで誰が「回答待ち」「稼働中」「完了」「待機中」なのかと、使っているモデルを一覧にする画面です。AI 利用枠の画面とは別に、同じサーバーから配信します。

```sh
./kindlemon install agents   # USB 接続中の Kindle に、ボード用のスクリプトを転送
```

ブラウザでは `./kindlemon url` の URL の末尾に `/agents` を付けると見られます。

| 列 | 内容と取得元 |
|---|---|
| 状態 | herdr のエージェント状態。`blocked`（承認・質問画面を検出）を「回答待ち」として最上位に反転表示します。herdr 外の Claude Code / Codex はセッション記録から「稼働中」「待機中」だけを判定します |
| 場所 | herdr のワークスペース名。herdr 外のセッションは作業フォルダ名 |
| 名前 | herdr のエージェント名、または Claude Code のセッション名（自動生成の英数字 ID は省略） |
| モデル | Claude Code・Codex はセッション記録、Antigravity は画面下部の表示から読み取ります。どれでも取れない場合は `models.yaml` のロール設定を使い、「設定」と表示します |
| 経過 | その状態になってからの時間。herdr 分はサーバーが観測し始めてからの時間です |

下段には agmsg の情報を表示します。

- **人間への問い合わせ**: 直近 3 日間に、人間（`human`・`you`・agmsg app 席）宛てに届き、まだ返信していないメッセージを、チーム・送信者ごとにまとめて表示します。本文は読み込みません。
- **最近動いたチーム**: 最後にメッセージが流れた時刻の新しい順です。

環境変数で取得元を変えられます。

| 変数 | 既定値 |
|---|---|
| `KINDLE_AGMSG_API` | `~/.agents/skills/agmsg/scripts/api.sh` |
| `KINDLE_MODELS_YAML` | `~/develop/neovista-git/consultingwork/hq/models.yaml` |

制限:

- agmsg app 内で動くエージェントの状態はアプリのメモリにしかないため、直接は読めません。Claude Code・Codex であればセッション記録から拾います。
- Antigravity のモデルは画面下部の表示から読み取るため、画面構成が変わると「不明」になります。読み取るのはモデル名だけで、画面の他の文字は保存しません。

## セキュリティ

- アクセスにはトークン（`.kindle_token`、パーミッション 600）が必要です。トークンを変えたいときはファイルを削除して `./kindlemon stop && ./kindlemon start` を実行します。
- 通信は HTTP（平文）です。自宅など信頼できる LAN でのみ使ってください。
- 認証情報はサーバー内でだけ使い、Kindle には送りません。会話本文も扱いません。
- 作業ディレクトリはフルパスではなく末尾のフォルダ名だけを表示します。

## 省電力の更新間隔

- 通常は、Macのデータ収集・画像生成とKindleの画像取得をそれぞれ5分間隔で行います（処理時間は別途かかります）。
- Kindleの画像取得に失敗すると、次の試行まで10分、20分、30分と間隔を延ばします。以後は30分を上限に再試行し、成功すると5分間隔に戻ります。
- 通信失敗時は最後の画像を残します。時計や使用率も古いままなので、収集時刻を確認してください。
- 待機中も5秒ごとに電源ボタンによるスリープを確認します。間隔を延ばしても、終了操作は待たされません。
- 既存のKindleにも適用するには、USBで接続して `./kindlemon install` を再実行し、取り出した後に「AI Monitor - Start」を起動し直してください。Mac側もサーバーの再起動が必要です。
- この変更は通信・描画の頻度を減らすものです。Wi-Fiやスリープ抑止は継続するため、電池持ちの改善幅は実機で確認してください。
